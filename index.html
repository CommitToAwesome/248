Military DDIL Communications Training Simulator

Technical Specification Document (Corrected Version)

SECTION 1: OPERATIONAL CONTEXT & TACTICAL REQUIREMENTS

Modern multi-domain operations occur in Denied, Degraded, Intermittent, and Limited (DDIL) environments. Adversaries actively employ Electronic Warfare (EW) to jam RF spectrums, spoof sensor feeds, and sever C2 links. Operators must be trained to recognize and fight through these environments using LPI/LPD (Low Probability of Intercept / Low Probability of Detection) techniques, Frequency Hopping Spread Spectrum (FHSS), and self-healing Mobile Ad-hoc Networks (MANETs).

Tactical AI Automation Bias Test

A critical training requirement is testing Automation Bias. The simulator intentionally feeds poisoned or spoofed sensor data to the trainees' tactical displays. Instructors evaluate whether operators blindly trust the degraded systems or cross-reference multiple sensors and human intelligence to override bad AI/system suggestions.

SECTION 2: CORRECTED SYSTEM ARCHITECTURE

This revised architecture addresses the unfeasibility of external packet manipulation with UE5's native replication. It employs Authoritative Server-Side Degradation.

Why Not an External Proxy?

UE5 uses proprietary delta-compressed bit-packing (FBitWriter/FBitReader) for network replication. Field positions change every tick. An external proxy cannot parse or mutate these packets. Spoofing must happen inside the authoritative server before replication.

Core Concept:

  • The Simulation State Server itself maintains TWO data layers: Ground Truth and Degraded View (per player).
  • When the instructor triggers EW, the SERVER modifies the Degraded View BEFORE replicating data to trainees via UE5's native replication system.
  • No external packet interception needed.
  • VoIP goes through a LiveKit SFU (Selective Forwarding Unit), NOT a dumb packet-dropping proxy.
  • Audio degradation happens CLIENT-SIDE via Web Audio API based on SINR values from the server.

Infrastructure Stack

  • Sim State Server (UE5/C++): Authoritative server maintaining Ground Truth AND Degraded View per player. Performs RF link budget calculations and applies instructor EW triggers before replication.
  • LiveKit SFU: Routes WebRTC VoIP. Keeps SRTP/DTLS sessions healthy. Audio degradation applied client-side.
  • Redis (Pub/Sub): Broadcasts instructor EW triggers to the server. Uses dual-write pattern (SETEX + PUBLISH) for crash recovery.
  • InfluxDB: Logs both Ground Truth and Degraded View at 10Hz for AAR Reality Delta analysis.
  • PostgreSQL: Stores AAR reports, user profiles, scenario configs.

Corrected DSP Implementation

The previous implementation had flaws in filtering and LFO gating. The corrected code is below.

Bandpass fix: Use two filters in series to create a flat 300Hz-3kHz passband mimicking tactical radios.

// CORRECTED: Two filters for flat 300Hz-3kHz passband const highpass = audioCtx.createBiquadFilter(); highpass.type = 'highpass'; highpass.frequency.value = 300; const lowpass = audioCtx.createBiquadFilter(); lowpass.type = 'lowpass'; lowpass.frequency.value = 3000; source.connect(highpass).connect(lowpass).connect(nextNode);

LFO Gating fix: Use offset/scale technique so the LFO modulates gain cleanly between 0 and 1.

// CORRECTED: Offset + Scale for true [0,1] gating const lfo = audioCtx.createOscillator(); lfo.type = 'square'; lfo.frequency.value = 4; // 4 Hz chopping const lfoScale = audioCtx.createGain(); lfoScale.gain.value = 0.5; // Scale [-1,1] to [-0.5,0.5] const gateNode = audioCtx.createGain(); gateNode.gain.value = 0.5; // DC offset: effective range [0,1] lfo.connect(lfoScale); lfoScale.connect(gateNode.gain); lfo.start();

SECTION 6: REDIS PUB/SUB EVENT SCHEMA

The instructor dashboard dispatches EW commands to the simulation server via Redis. We use a dual-write pattern (SETEX + PUBLISH) so late-joining simulation nodes can recover the active jamming state.

SECTION 7: INSTRUCTOR DASHBOARD

The web-based instructor interface controls the DDIL scenario in real-time, composed of three main zones:

  • COP Map (Common Operational Picture): Features a Ground Truth vs. Trainee View toggle and a live RF Heatmap overlay calculating path loss and jamming footprints.
  • Chaos Controls: Drag-and-drop tools for sector jamming, targeted cyber injections, and intensity sliders utilizing ramp_up_sec for subtle degradation over time.
  • Comms Matrix: A live node graph visualizing voice and data link health (green/yellow/red), along with a "God Mic" override button to speak directly to trainees regardless of simulated network state.

SECTION 8: AAR COGNITIVE DNA PROFILER

The After Action Review (AAR) engine compares the timeline of Ground Truth against what the Trainee Perceived, and what Action they took. This isolates cognitive failure points (e.g., Automation Bias).
